How it works

Three small model calls instead of a browsing session.

1 · Compile

Read the request

Turn it into a search term, hard filters, a sort order and the attributes that must be true.

1 model call
2 · Search

Query the catalog

Search merchant catalogs and apply price, rating and review filters in code, not in the model.

0 model calls
3 · Shortlist

Pick the contenders

Narrow the filtered results to the two products most likely to meet every requirement.

1 model call
4 · Verify

Check the product page

Check every requirement against specs and reviews, then return one product with its reasons.

1 model call
Then checkout: UCP→ACP→Universal→Browser · automatic fallback, spend limits, human approval above your threshold
API

One key. Search and checkout.

Use it over HTTP or as an MCP server in Claude and any other MCP client. Your agent never sees card details: each order gets a single-use payment token capped at the order total.

# find one product that fits
POST /v1/search
{ "query": "wireless ANC earbuds under $80, 4.3+ stars, cheapest first" }

# → { "productId": "amazon:B0DD41G2NZ", "price": 27.99,
#      "why": ["45dB hybrid ANC", "4.3★ from 50,428 ratings", ...] }

# buy it, through whichever route the merchant supports
POST /v1/checkouts
{ "items": [{ "productId": "amazon:B0DD41G2NZ", "quantity": 1 }] }

POST /v1/checkouts/:id/complete
# → status: "completed", routeAttempts: ["✓universal"]
